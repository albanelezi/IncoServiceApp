## 0. Read this first: the ten things that will bite you

1. **Edit `INCO_Furniture_v12.src.html`, never `INCO_Furniture_v12.html`.** The `.html` is generated by `node _minify-main-script.js` and is what Firebase Hosting serves. Edits to it are overwritten on the next build.
2. **Firestore rules default-deny any collection not listed.** The live rules are `firestore.rules` ("Pass A"). If you add a collection, or the merged app uses one with a different name, it must get a `match` block **and** `firebase deploy --only firestore:rules`. Otherwise every read and write is rejected, and a batch containing it fails as a whole. This exact mistake broke order deletion for 18 days (Sep 18 to Oct 6, 2026).
3. **Never deploy `firestore.passB.rules`.** It is the role-aware ruleset, and it depends on the `partner_index` collection, which is **empty** in production. Deploying it would lock out every partner.
4. **Never write an order's whole `blocks` array from an in-memory copy.** Every workflow write is a transaction that re-reads the order and changes one section, matched by `block.id`. Whole-array writes from stale copies silently rolled back other devices' work; fixed 2026-10-06. See §9.
5. **`porosite` and `porosite_index` must always be written together, in the same transaction.** At boot the app loads only `porosite_index`. An order missing from the index is invisible.
6. **Hosting publishes the whole project folder** (`"public": "."`). Until 2026-10-06 that included `.git/` and customer WinCut files. A correct deploy prints `found 2 files`. If you see more, stop and check what is being published.
7. **No backups.** Point-in-time recovery is OFF, delete protection is OFF, and there are no scheduled exports. Take an export before any database merge or migration (§14.3).
8. **`block.id` is unique only within one order** (a per-order counter, `blockIdCtr`). The visible section number `#<fatura>-<n>` is the 1-based *array position*. It changes if a section is inserted or removed. Anything stored long-term must key on `(orderId, block.id)`, never on the position.
9. **Inline `onclick="fn(...)"` handlers call top-level global functions by name.** The minifier deliberately keeps top-level names. If you move code into ES modules or a framework, those functions must stay on `window`.
10. **Old browser tabs keep running old code.** Since 2026-10-06 a banner ("🔄 Ka një version të ri…") asks tabs to reload after a deploy. A schema change still needs every shop tablet reloaded before old code writes to it.

## 1. What the app is

INCO is a furniture-panel workshop in Albania. The app, written in Albanian, is a single-page web app for:

- **Clients** (*Klientët*) and **orders** (*Porositë*). An order has one or more **sections** (*seksione*, code name `blocks`). Each section is one material + board format, with **rows** of pieces (length, width, quantity, edge banding, painting, milling).
- **Cut optimisation.** A strip-packing optimizer runs in a Web Worker in the browser. It lays the pieces out on boards (*pllaka*, code name `panels`) and generates **WinCut `.txt` programs** for the shop's beam saw, plus PDFs (cut sheets, labels, invoice).
- **Pricing and invoice** per section (§11).
- **Shop-floor workflow** (*Menaxhimi*): four departments per section, Saw → Edge banding → CNC → Painting. The painting department has six timed steps (§10).
- **Kanban** order status: Në Pritje (waiting) → Në Procesim (in progress) → Përfunduar (finished) → Dorëzuar (delivered).

**Roles** (resolved client-side in `resolveRole`, line 4330):

- **Admin.** Exactly one email: `ADMIN_EMAIL = 'albanisela@gmail.com'` (line 4310). Sees everything.
- **Partner.** A signed-in user whose email matches a `klientet` doc with `isPartner: true`. Partners see only clients and orders whose `createdBy` is their own client id. They can't change workflow or paint times.
- **Anyone else** is signed out immediately with "Pa akses për këtë email".
- ⚠ Role enforcement is **UI-only**. The live rules (Pass A) let *any* signed-in user read and write *everything* (§8).

## 4. Build and deploy

```bash
# 1. edit INCO_Furniture_v12.src.html
# 2. (only if functions/ optimizer code changed) rebuild + re-embed the worker:
node bundle-worker.js            # → optimizer-worker.js, .min.js (npx terser), .obf.js (npx javascript-obfuscator)
node _install-local-optimizer.js # embeds the .obf (or .min / raw) bundle into src.html
# 3. build the served page:
node _minify-main-script.js      # → INCO_Furniture_v12.html
# 4. verify (see §15), then deploy:
firebase deploy --only hosting --project incoservice-4e196          # expect "found 2 files"
firebase deploy --only firestore:rules --project incoservice-4e196  # only when firestore.rules changed
```

- The minifier keeps top-level names (`--mangle` without `toplevel`). Inline handlers depend on that.
- The hosting ignore list in `firebase.json` excludes dot-folders (`**/.*/**`, `.git/**`), `*_WINCUT/**`, `*.txt`, `*.md`, `handover-tools/**`, `*.rules`, `_*.js`, `functions/**`, the source HTML and the worker artifacts. After a deploy the only public files are `INCO_Furniture_v12.html` (every path rewrites to it) and `package-lock.json`.
- Both `.src.html` and `.html` are committed. Commit messages end with a `Co-Authored-By:` line.

## 7. Firestore database: full schema

**Conventions** (watch these when merging):

- **Times** come in four forms:
  - epoch **milliseconds as integers**: `doneAt`, `createdAt`, `startMs`, `mtime`, …
  - ISO strings: `porosite_trash.deletedAt`
  - `'YYYY-MM-DD'` strings: `order.data`, `paint_sessions.startDay/endDay`
  - Firestore **Timestamps**: `serverCreatedAt`, `serverEndedAt`, `partner_index.mtime`
- **Numbers stored as strings.** `rows[].l`, `g`, `s` are always strings. `ag` / `as_` are a mix of string and integer. Read them with `parseFloat` / `parseInt`.
- **Ids.** Orders use a numeric doc id (string form of the integer `id`). Clients use `klt_<epochMs>_<rand>`. Workers and paint sessions use Firestore auto-ids.
- **No sub-collections.** All root collections are listed below. `porosite_trash` and `partner_index` don't currently exist, because they have no documents.

### 7.1 `konfig` (4 fixed docs)

Read by everyone; written by `savePrices` (line 7158) in **one transaction** with optimistic locking: each doc carries `_saveStamp`, the save aborts if any stamp changed, and on success all stamps are bumped.

| Doc | Fields |
|---|---|
| `global` | `cutting`, `painting`, `frezim` (int Lek, **unused by order pricing since 2026-08**), `_saveStamp` |
| `formats` | `items[]: {id:'fmt_…', lung, larg, thickness}` (mm), `_saveStamp` |
| `materials` | `items[]: {id:'mat_…', type, description, mePrimoso?, subType?, prices:{<formatId>: Lek}}`, `_saveStamp`. A material shows up in the order picker only for formats it has a price for. |
| `tenies` | `items[]: {id:'t_…', description, price22, price28, price40, price56}`, `_saveStamp`. Legacy 4-tier banding prices, unused for pricing now. |

### 7.2 `klientet/{klt_…}` (63 docs)

`{ id, emri (name), telefoni, email, adresa, isPartner: bool, createdBy: 'admin' | <partner klient id> }`.

- Written by `saveKlient` / `upsertKlient` (full `set`).
- Names are unique (case- and whitespace-insensitive check in the UI).
- `delKlient` cascades: it moves every order of the client to the trash, deletes their `porosite`, `porosite_index` and `kanban` docs, deletes `counters/fatura_<id>`, then the client.

### 7.3 `porosite/{orderId}` (222 docs): the full order

Top level:

| Field | Type | Notes |
|---|---|---|
| `id` | int | Global id from `counters/porosite` (`allocateOrderId`). **Never reused**: deletes no longer rewind the counter. |
| `fatura` | string | Per-client invoice number from `counters/fatura_<klientId>` (`allocateFaturaForKlient`, starts at 100) |
| `klient_id` / `klient_emri` | string | `klient_emri` is a snapshot; the UI shows the live name from `klientet` |
| `data` | string `YYYY-MM-DD` | Order date |
| `klientNote` | string | Free-text note (form + PDF header) |
| `total` | int Lek | Sum of `calcBlockPrice(b).pTotal` at save time |
| `createdBy` | string | `'admin'` or the partner's klient id; preserved on edits |
| `blockIdCtr` | int | Next `block.id` for this order |
| `priceSnapshot` | map | Legacy price-drift snapshot `{services:{cutting,painting,frezim}, blocks:[{materialId, formatId, tenieId, matPrice, fmt:{lung,larg,thickness}, tenie:{price22..56}|null}]}`. Still written; drift UI disabled (`SHOW_PRICE_DRIFT=false`). |
| `blocks` | array | The sections, below |

`blocks[]`, one per section:

| Field | Notes |
|---|---|
| `id` (int) | Unique **within the order only**. The stable key for workflow and paint records. |
| `materialId`, `formatId`, `tenieId` | References into `konfig` items |
| `type` | `mel` / `bet` / `mdf` / `lis` (colour bucket) |

| `rows[]` | Pieces, below |
| `rowIdCtr` | Next row id |
| `panels[]` | Optimizer output, below. **Shared by reference between "sibling" sections** with the same `materialId|formatId` (one optimisation per group); each sibling stores its own copy in Firestore. |
| `priceP`, `priceCut`, `priceBoard`, `pricePaint` | Per-section prices (Lek): board / cut per panel / banding per metre / paint per m² |
| `kodiBojes` | Paint colour code |
| `printLabels` | bool: whether WinCut files carry label references |
| `dimMode`, `dimAdd`, `cutDir` (`'auto'`/`'X'`/`'Y'`), `optAlgo` (`'v3'` default / `'classic'`), `collapsed` | UI and optimizer settings |
| `totCope`, `totML`, `totML22/28/40/56`, `totM2`, `totM2sip`, `totM2ans`, `totPaint`, `kgMbuluese`, `kgUji` | Computed by `calcBlock` (line 9451) and persisted. Recompute rather than trust. |
| `_optDirty`, `_optFingerprint`, `_optRunning`, `_partial`, `_partialReason`, `_importJob` | Block-level transient fields that leak into the DB (`stripTransientFromBlocks` only drops `_optTimer`). Ignore them; `_optRunning: true` can be stale. |
| `workflow` | Shop-floor state (§10) |

`blocks[].rows[]` (factory `makeRow`, line 8373):

- `{id, l, g, s, ag, as_, anen:'1A'|'2A', lyerje: bool, frezim: bool, frezimPrice, grainLock: bool, groupColor, koment, fromDopjim: bool, parentRowId, side, doubledSides: {gjate: 0|1, shkurter: 0|1}}`
- PDF-import fields are kept on save: `_fromPdf`, `_importCode`, `_importCodeBack`, `_importCaseNumber`, `_importPart`, `_importJob`.
- Older orders also carry stale computed `_m2`, `_ml*`, `_m2sip`, `_m2ans`.

`blocks[].panels[]` (optimizer output, one entry per board):

- `{mode: 'X'|'Y', strips[], rows[] (summary {type, val, qty, tid}), vis[] {x,y,w,h,tid} (2D preview), cuts[] {h, x,y,x1,x2,y1,y2}, eff (%), placedCount, content (WinCut .txt WITH label injection), _rawContent (pristine optimizer .txt), noPrice: bool, _manualEdit: bool, _splitInfo}`
- Strip geometry:
  - X mode: `stripW`, `uPh`, `uQty`, `ru`, `vBars[] {vPw, barH, vQty, ru, typeId}`
  - Y mode: `stripH`, `primaryCuts[] {pw, ph, qty, typeId}`, `offcuts[] {xPw, ru, uCuts[] {uPh, uQty, typeId}}`

**Document size.** The average order is about 45 KB. The largest is about **310 KB** (207 KB of it panels) against Firestore's **1 MiB** limit. Panels carry the full WinCut text twice (`content` plus `_rawContent`). A very large order with many sections could approach the limit.

### 7.4 `porosite_index/{orderId}` (222 docs): order summaries

Built by `_summaryOfOrder` (line 5034):

`{id, fatura, klient_emri, klient_id, data, total, createdBy, priceSnapshot, block_summaries: [{type, name, materialId, formatId, tenieId}], mtime}`

- Written in the **same transaction** as `porosite` (`persistOrder`, line 5424).
- `block_summaries` let Konfigurim refuse to delete a material or format that saved orders still use.

### 7.5 `kanban/{orderId}` (220 docs)

`{col: 'pritje'|'procesim'|'perfunduar'|'derguar', phases: {}}`

- A missing doc means `pritje`. `phases` is legacy and always empty.
- Written with a full `set` by `persistKanbanForOrder`. `derguar` (delivered) makes the order read-only.
- A column move (`moveKbOrderTo` → `_wfApplyOrderColumnTransition`, line 16151, transactional) **rewrites the workflow**:
  - to `perfunduar` / `derguar`: every applicable stage and all paint steps become `done`
  - to `procesim` / `pritje`: everything resets to `pending`
  - any move: paint locks are cleared and running paint timers are closed

### 7.6 `counters` (63 docs)

| Doc | Content |
|---|---|
| `porosite` | `{next}`: global order id allocator, currently 347 |
| `fatura_<klientId>` | `{next}`: per-client invoice allocator |

Both are incremented in transactions. Fatura allocation also seeds from the highest fatura in the cache, so a missing counter never produces a duplicate.

### 7.7 `porosite_trash/{orderId}` (0 docs right now): soft-deleted orders

`{order: <full porosite doc>, kanban: <kanban doc>|null, deletedAt: ISO string, deletedBy: 'admin'|klientId}`

- Written in the same batch as the delete (`deleteOrderById`, line 5474; `delKlient`).

- A restore re-creates `porosite`, `porosite_index` and `kanban`. If the id is taken it allocates a new one and bumps `counters/porosite`.

## 9. Concurrency rules (follow them in merged code)

The order doc holds all sections in one array. Several devices write to the same order: the office editor, the saw / banding / CNC / paint tablets, and kanban moves.

1. **Workflow writes** go through `_wfTxUpdateBlocks(orderId, blockId, idxFallback, mutate)` (line 17307). It runs a transaction that reads the current doc, finds the section by `block.id`, lets `mutate` change only that section's `workflow`, and writes `blocks` back. Users of this pattern: `wfApplyStageChange`, `wfDrawPersist` (CNC drawings), all paint-timer transactions, and `_wfApplyOrderColumnTransition`.
2. **Editor saves** (`persistOrder`) are also a transaction. They keep the **server's** `workflow` for every section, matched by id. The one exception is the CNC drawings in `workflow.cnc.designs`: the editor's copy wins when its newest `updatedAt` is newer. The editor never rolls back shop-floor progress.
3. After a write, `_wfSyncWorkflowCaches(orderId, freshBlocks)` copies the server workflow into every in-memory copy. If the set of sections changed, it marks the department cache stale.
4. `_wfKanbanFlipAfterChange`:
   - When the whole order is done, it moves the order to Përfunduar.
   - When the first piece of work is done on a Pritje order, it quietly sets Procesim. It deliberately avoids `moveKbOrderTo`, because that would reset every stage.
5. Saving the order editor is serialised (`window._saveOrderInFlight`) and its buttons are disabled while it runs. This fixed a duplicate-order bug.
6. Konfigurim uses optimistic locking (`_saveStamp`, §7.1).

## 10. Workflow and paint time tracking

**Stages per section** (`WF_STAGES = ['saw','board','cnc','paint']`, line 16349). Applicability is derived, not stored (`wfApplicableStages`):

| Stage | Applies when |
|---|---|
| saw | always |
| board | the material has edge banding |
| cnc | any row has `frezim` |
| paint | the material is paintable and any row has `lyerje !== false` |

A stage is `locked` until all earlier applicable stages are `done`. Stored statuses are only `pending` / `done`; legacy `inProgress` reads as pending.

`blocks[].workflow` shape (created and migrated by `wfEnsureBlockWorkflow`, line 16402):

```js
{ saw:   {status, doneAt},
  board: {status, doneAt},
  cnc:   {status, doneAt, designs: [{id, updatedAt, pages: [{pageIndex, pageWidth, pageHeight,
                                     strokes: [{type, x, y, w, h, color, width, text, fontSize}]}]}]},
  paint: {status, doneAt, subVersion: 2, substages: {
    zmerilimShqeto | lyerjePaste1 | zmerilimPaste1 | lyerjePaste2 | zmerilimPaste2 | lyerjeBoje : {
      status, doneAt, doneBy, doneSource: 'timer'|'no-time', m2AtDone, piecesAtDone, workMsAtDone,
      history: [{action: 'done'|'revert', atMs, by}], revertedAt, revertedBy, migratedFrom: 'v1'?,
      openSessionId, openSince },   // ← the lock: id of the running paint_sessions doc
    zmerilim | pateDora1 | pateDora2 | lyerje : {...}   // legacy v1 keys, kept for traceability, ignored
  }} }
```

**Paint steps, in physical order and strictly sequential:**

| # | Key | Label | Kind |
|---|---|---|---|
| 1 | `zmerilimShqeto` | Zmerilim shqeto | sanding |
| 2 | `lyerjePaste1` | Lyerje dora parë pastë | coating |
| 3 | `zmerilimPaste1` | Zmerilim pastë dora 1 | sanding |
| 4 | `lyerjePaste2` | Lyerje dora dytë pastë | coating |
| 5 | `zmerilimPaste2` | Zmerilim pastë dora 2 | sanding |
| 6 | `lyerjeBoje` | Lyerje me bojë | coating |

When all six are done, `paint.status` becomes done.

**Migration from the old 4-step model.** It runs once per section (gated on `subVersion !== 2`) and is cumulative and conservative:

| Old state | New steps marked done |
|---|---|
| old `lyerje` done, or paint done | all 6 |
| `pateDora2` done | first 4 |
| `pateDora1` done | first 2 |
| `zmerilim` done | first 1 |

**Timer state machine** (`ptAction`, line 17921). Every action first re-reads the server (`_ptFreshen`), and each one is one transaction:

| Action | What it does |
|---|---|
| Start / resume (`_ptTxStart`) | Picks workers, then in one transaction checks the step is pending, checks no live lock, creates the session and sets `openSessionId` / `openSince`. A lock that points at a closed, deleted or missing session is treated as stale and ignored. |
| Pause / finish (`_ptTxClose`) | Closes **every** open interval of the step, releases the lock, and on finish marks the step done with its metrics |
| Revert (`_ptTxRevert`) | Only the latest done step, and only if the next step isn't running and has no time recorded |
| Manual add / edit / delete (`ptSaveForm`, `_ptTxAddClosed`, `_ptTxEditSession`, `_ptTxDeleteSession`) | Overlap check. An edit writes only the fields the user changed compared with what the form showed, so a stale form never undoes another device. Reopening takes the lock; closing releases it. Every edit is audited. |
| Stray timers | The Lyerje tab shows a banner listing every running interval that isn't visible on a Lyerje card (for example, a timer left on a step that is no longer the active one). Each has ■ Ndalo (`ptStopOrphan` → `_ptTxStopSession`), and any running longer than 10 h is shown in red. |
| Read-only | Partners and the read-only order overview get no buttons (`_ptIsReadOnly`) |

Network calls time out after 20 s (`_ptNet`), so offline tablets get an error instead of frozen buttons.

## 11. Pricing (per section since 2026-08-10)

`calcBlockPrice(b)` (line 9573) uses **only the section's own prices**. Konfigurim prices are unused.

| Component | Formula |
|---|---|
| Panels | billed panels × `priceP` |
| Cut | billed panels × `priceCut` |
| Banding | `totML × priceBoard` (if the material has banding) |
| Paint | `(totM2sip + totM2ans) × pricePaint` (if paintable) |
| Frezim | Σ over milled rows of `frezimPrice × s` |

- **Siblings** (same material and format) share panels. Panel and cut cost is charged once, on the first sibling.
- Panels with `noPrice: true` (the shop used a warehouse remnant) are excluded from panel and cut cost.
- "Shkarko / Printo Faturën" saves first, then refuses to build the invoice if any section is missing prices.
- Money is rounded to whole Lek.
- `HIDE_PRICES = false`, `SHOW_PRICE_DRIFT = false` (lines 3803–3809).

Paint quantities (`calcBlock`):

- `m2sip = L×G/1e6 × s × (2 if '2A' else 1)`
- `m2ans = (2L+2G) × thickness/1e6 × s`

Both are counted only for rows with `lyerje !== false` in paintable materials.

## 12. Optimizer and WinCut export

- **Running it.** `runOptimizer(bid)` (line 14404) pools the rows of every sibling section and calls `runOptimizerLocal`. That function spawns a Worker from the embedded bundle and returns `{panels: [{mode, strips, rows, content, eff, placedCount}]}`. The client then adds `vis` / `cuts` for previews and injects label codes.
- **Source and tests.** The source is in `functions/`; see README.md for the algorithm. Tests: `cd functions && node test-equivalence.js && node verify-cuts.js`.
- **Saving files.** `shkarkoWincut` saves the order, then writes one `.txt` per board into a folder `<klient>_<fatura>_WINCUT/` (File System Access API, or a zip fallback). File names look like `<klient>_<fatura>-<subNos 001-002>_<section name>_<NN>.txt`; split boards get `_A` / `_B`.
- **Labels.** `content` holds labels re-derived from the current rows at export time (`_rebakeBlockLabels`), but only when `_rawContent` still matches the board's strips.
- **Manual editor.** `openManualEditor` (line 11203) lets the operator drag pieces. Its output and the optimizer's both go through geometric envelope validators (`_meAssertWincutRowsValid`, line 12378, and the packer's `assertWincutRowsValid`), so a file the saw can't cut is never written. Fixed 2026-09-09 after the "Agron Kurti 103" incident.
- **PDF import.** `_pdfImport*` (line 19404+) reads label PDFs with pdf.js and creates sections and rows with import codes.
- **Where files live.** WinCut files are **not stored in Firebase**. They exist only on the operator's disk and inside the order doc (`panels[].content`).

## 18. Bilanc link (added 2026-10-09)

Every saved order is billed in **Inco Bilanc** (the accounting app, Firebase project `incobilanc`, repo `github.com/albanelezi/incobilanc`).

- **Where:** one block in `INCO_Furniture_v12.src.html` named "BILANC LINK", just before the Koshi section. Three one-line hooks call it: `persistOrder` (after a successful save) and `restoreTrashedOrder` call `bilancSyncOrder(order)`, and `deleteOrderById` calls `bilancRemoveOrder(id)`. Nothing else changed. The optimizer engine is untouched and must stay that way.
- **How:** `_bilancLoadBridge` loads `https://incobilanc.web.app/service-bridge.js`, a script built from Bilanc's own code (`src/integrations/serviceBridge.js`). It writes only to the Bilanc database, never to this app's database.
- **Payload:** `_bilancOrderPayload(order)` works on a copy of the saved order. It uses `calcBlock` plus the same sibling, "Pa çmim" and frezim rules as `calcBlockPrice` / `buildInvoicePDF`, with the sibling rule applied within the order itself. On all 222 live orders the Bilanc total matched `calcBlockPrice` within 1.7 Lek (quantities carry 3 decimals).
- **Bilanc side:** up to three Faturë shitje per order, one per department, all with the order's reference (`serviceFatura`). Each is created only when its department has something to bill:
  - `svc-<id>-boards`: the boards, from Magazina Qendrore (stock leaves there)
  - `svc-<id>-machining`: cutting, Bordim and Frezim, from Reparti makinerive
  - `svc-<id>-painting`: m² of painting, from Reparti i lyerjes

  Saving the order again updates them, creates newly needed ones and removes ones no longer needed. Fiscalized or paid invoices, and invoices edited by hand in Bilanc (`serviceEdited`), are left alone; the workshop is warned once per order change. An invoice deleted by hand in Bilanc is never recreated. Deleting the order removes the rest.
- **No configuration:** warehouses are found by name. Orders dated before 2026-10-09 (`SERVICE_START_DATE` in the bridge) are not billed, because they were invoiced by hand.
- **Never blocks a save:** the call runs after the save. A failure shows a toast, and saving again retries. Partners get no toasts.

## 19. Materials from Bilanc, no prices (added 2026-10-09)

- **Catalog:** materials, formats and tenie variants are read from the **articles of Inco Bilanc**, not from `konfig`. The block is "MATERIALS FROM INCO BILANC" (`applyBilancCatalog`, `buildCatalogFromBilancItems`, `_bcSection`, `_bcParseFormat`). It runs at boot right after `konfig` (step 1.5), through a second, read-only Firebase app named `bilanc`.
  - Section from the article name, checked in this order: tenie / tenije / bordim → Tenie; fiber; betoform; mdf; mel. "Sherbim …" articles are skipped.
  - Format from the dimensions in the name (`3660 x 1830 x 18`, `3660*1830*18`, `3660 1830 18`). Centimetres are read as mm; the thickness defaults to 18.

  - Ids: `bm_<section>_<name>`, `bf_<L>x<W>x<T>`; tenie = the article id. `material.items[formatId]` is the article. A block stores `bilancItemId`; `_materialOfBlock` resolves through it if an article is renamed.

It was tested on all 380 live sections: none changed material, format, tenie or stages. If Bilanc can't be read, the app keeps the konfig catalog and shows a toast.
- **Konfigurim:** the material tabs are read-only (`body.catalog-bilanc` CSS; `savePrices` refuses), with a note and a link to Bilanc → Artikujt. Workers are unchanged.

Invoice prices come from Bilanc's articles (see §18; the payload sends `bilancItemId`, `bilancTenieId` and `frezimPieces`).
- **WinCut labels:** `_injectCodesIntoTxt` resolves the material text through `getMaterialById` / `getFormatById` when they exist, so old orders keep their label text. `_test-dati-format.js` passes. The optimizer is untouched.
- **Bilanc project (Inco Furniture orders only, required):** orders of "Inco Furniture" or "Inco - Furniture" (`_isIncoFurnitureName`) show a "Projekti (Bilanc)" select with all open Bilanc projects. Projects exist only for Inco Furniture. The order can't be saved without a project (`_bilancProjectOk`); orders dated before 2026-10-09 are exempt, and partners are never blocked. The choice is stored as `bilancProjectId` + `bilancProjectName`, counts in `fullFingerprint`, and is sent as `payload.projectId`. Bilanc then creates internal **project documents** (PROJECT_DOC), not sales invoices: no revenue, no client debt, stock moves as usual (Dr 331 / Cr 351). Other clients have no project.
